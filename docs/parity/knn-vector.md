# knn_vector -- the k-NN plugin's vector field and knn query

[Index](../parity.md). Not a Lucene module: OpenSearch's k-NN plugin
(3.9.0.0) owns `knn_vector` and `knn`; the lucene-rust plugin serves both
itself, on Lucene's vector formats, searched in Rust. Plan and stages:
`/mnt/project-files/plan/knn-vector-native.md` in the project notes.

| Java | Rust | Status |
|---|---|---|
| -- (k-NN `KNNVectorFieldMapper`, `KNNMethodContext`, `EngineResolver`, `ModeBasedResolver`, `KNNSettings`) | `opensearch-plugin/.../knn/{KnnVectorFieldMapper, KnnFieldConfig, SpaceType, KnnSettings, KnnVectors}.java`, `.../engine/VectorsFormatSpec.java`; `lucene-ffi/src/engine_writer.rs::{decode_vector_schema, parse_vectors_format}` | **rust-only** (mapping side). dimension; data_type float, byte, binary, half_float (1x, ±65504, cosine normalized); space_type l2/cosinesimil/innerproduct/hamming (hamming for binary only, its default); hnsw on lucene (m, ef_construction; no engine means lucene, `engine: faiss` refused); sq bits 7/4/2/1, mode, compression_level, doc_values, store. The field's format travels as `lucene_rust.knn_format`; OpenSearch's own engine writes the same formats (`knn/codec/KnnCodecService.java`). Derived source: a new knn index turns it on (and stock's merge settings); on the Rust engine without realtime search `knn/DerivedSource.java` masks vectors in the stored `_source` (a nested field's from its child documents, in order) and marks the field `lucene_rust.derived_source` (`true`, or `nested`) for the Rust writer. `GET _mapping` persists the resolved method as stock does; `docvalue_fields` (`binary`, `array`) and `stored_fields` read as stock's (`KnnVectorFieldData.java`). Gap: half_float 16x (refused), l1/linf, faiss and models. Tests: `decode_field` schema tests; `scripts/check-knn-plugin.py`, `scripts/check-knn-rest.py`. |

Tests: `knn_search_explicit.rs`, `knn_nested.rs`, `jvm_knn` decode test, `NativeSelfTestKnn` (native against Lucene's own KNN queries); `scripts/check-knn-plugin.py`: stock's hits and scores. |
| -- (k-NN `KNN910Codec` ... `KNN1040Codec`, its SQ formats, `KNN9120HnswBinaryVectorsFormat`, `KNN1040HnswHalfFloatVectorsFormat`, `KNN1040HalfFloatFlatVectors*`) | `opensearch-plugin/.../knn/codec/*.java`; `lucene-codecs/src/codecs.rs::OPENSEARCH_KNN_CODECS`, `lucene-codecs/src/vectors.rs::{scores_hamming, stores_half_floats, f32_to_f16, FlatVectorsReader::resolve_similarities}`, `per_field_knn_vectors.rs::KnnVectorsFormat::{HnswHamming, HnswHalfFloat}` | **rust-only** (k-NN's codecs, both ways). Each codec is a `FilterCodec` over its Lucene delegate with k-NN's compound format; the binary format is Lucene99 HNSW over packed bits scored `1 / (1 + hamming)`; the half-float format is a Lucene99 HNSW graph over half-float flat files (similarity from `FieldInfos`, cosine scored `(1 + dot) / 2` like k-NN's FP16 kernel). So lucene-engine indexes k-NN wrote open in place or from a snapshot, take writes and merge, and stock reads what this plugin writes. Derived source: `DerivedSourceStoredFieldsFormat.java` and `lucene-search/src/derived_source.rs` put vectors back into `_source`; the Rust writer writes k-NN indexes under `KNN1040Codec` (`engine_writer.rs::OPEN_KNN`) and merges keep the sources' `derived_vector_fields` (`lucene-index/src/index_writer/segment_attributes.rs`). Gap: faiss segments, half-float SQ formats. Tests: `opensearch_codecs_read_as_their_delegates`, `knn_hamming.rs`, `knn_half_float.rs`, `half_float_conversion_matches_java`, `derived_source_fields_are_listed_kept_by_merges_and_read_back`; `scripts/check-knn-upgrade.py` (both directions, in place and by snapshot, `_source` by search and multi-get). |
| -- (k-NN `RestKNNStatsHandler`, `RestKNNWarmupHandler`, `RestClearCacheHandler`, `KNNStatsTransportAction`, `KNNWarmupTransportAction`, `ClearCacheTransportAction`, `KNNStats`) | `opensearch-plugin/.../knn/rest/{KnnRestHandlers, KnnStatsTransport, KnnShardsTransport, KnnStats, KNNInvalidIndicesException}.java` | **rust-only** (port of k-NN, REST side; registered only when stock k-NN is not installed). `_plugins/_knn/[{nodeId}/]stats[/{stat}]` and `?stat=` with stock's action name, response layout (`_nodes`, cluster stats, `nodes`), stat names and groups, and stock's 400s for an unknown stat or `_all` mixed with names; the query counters (`knn_query_requests`, `min_score_*`, `max_distance_*`, each with filter) count per shard as stock does. `warmup/{index}` opens a searcher on each knn shard; `clear_cache/{index}` has no native graph cache to drop and answers like stock; both reject a non-knn index with stock's `KNNInvalidIndicesException`. Native-memory, graph-cache, faiss/nmslib, script and training stats are reported at their idle values (no native graph cache). Tests: `scripts/check-knn-rest.py` (stats keys and counters, warmup/clear_cache shards and errors, against a stock node). |
