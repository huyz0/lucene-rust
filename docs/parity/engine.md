| (none: Rust-only) searching and fetching the engine writer's buffered documents without a refresh | `lucene-ffi/src/live.rs::{ffi_engine_writer_live_view_open, ffi_jvm_reader_search_live, ffi_live_view_document_alloc, ffi_live_view_reader, ffi_live_view_close, ffi_engine_writer_release_live}`, `lucene-index/src/concurrent_writer/live.rs::{live_buffer_segment, live_published_segment}`, `lucene-search/src/directory_reader.rs::with_readers_appended`, `lucene-ffi/src/engine_writer.rs` (`OPEN_LIVE_SEARCH`) | **Rust-only**. A view beside a reader of commit N reads the buffers that commit lacks; a buffered hit is numbered after the reader's `maxDoc`; a query the buffers cannot answer reports unsupported; the delete terms issued since commit N clear the reader's live docs (resolved once per reader, then incrementally). Otherwise the buffers are written as in-memory chunks of consecutive documents, kept across views (a view writes only newer documents), and appended to the reader. Given the request (query, aggregation tree), the chunks are written without postings and each gets only the request's terms sliced from the buffer, with the chunk's own field statistics (`range_segment`, `SegmentReader::with_postings`); prefix, wildcard and regexp clauses read the buffered terms they match, rescore queries come with it; fuzzy, span and other expanded queries get full chunks. A background thread writes new lean chunks every 5 ms, off the slot lock; a search absorbs at most 4096 documents and waits only for a chunk being written from its chain's end. A buffer being flushed or an index sort refuses.
