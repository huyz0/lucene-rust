# lucene-ffi -- the OpenSearch plugin boundary (M2, M5.6)

[Index](../parity.md). Pinned OpenSearch: **3.8.0** (its `lucene_version` is
10.5.0). The plugin is `opensearch-plugin/`; which requests run native, and
why the rest fall back, is [`docs/opensearch-native-queries.md`](../opensearch-native-queries.md).
The engine (write side) is [engine.md](engine.md); geo queries are
[plugin-geo.md](plugin-geo.md). The plugin-facing search features themselves
(sorts, aggregations, `terminate_after`, fetch) are in the `search-*.md` files.

| `index/StandardDirectoryReader` (an NRT reader's view: own `SegmentInfos`, in-memory live docs) + `index/SegmentInfos.write` | `lucene-ffi/src/jvm_reader.rs::{ffi_open_jvm_reader, ffi_jvm_reader_search, ffi_close_jvm_reader, ffi_jvm_abi_version, JVM_ABI_VERSION, decode_node}` | **ported** M2, extended through M9; ABI **33** (`JVM_ABI_VERSION`'s doc comment is the history). One native reader per Java searcher reader, opened from the bytes `SegmentInfos.write` produces (parsed by `segment_infos::parse`), checked per segment against the JVM's `maxDoc`s, masked with the JVM's live docs (which replace the on-disk `.liv`/soft-delete view). Handle immutable, held as an `Arc`: a search runs with no lock held, so a slow query never blocks a refresh. Segments memory-mapped (`MmapDirectory`); a refresh passes the previous handle and reuses unchanged segments (`reopen_at`). ## M10 T10.7: joins, spans, intervals, combined fields, function score

OpenSearch 3.8.0 shapes: **native** (encoded by the plugin's `ExtendedEncoder`)
or **falls back** (named reason). Proved by `NativeSelfTestM10` (hits, score
bits, counts, sorts, aggregations vs Lucene) and `e2e/m10_matrix.py`.
