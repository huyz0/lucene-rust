# lucene-ffi -- the OpenSearch plugin boundary (M2, M5.6)

[Index](../parity.md). Pinned OpenSearch: **3.8.0** (its `lucene_version` is
10.5.0). The plugin is `opensearch-plugin/`; which requests run native, and
why the rest fall back, is [`docs/opensearch-native-queries.md`](../opensearch-native-queries.md).
The engine (write side) is [engine.md](engine.md); geo queries are
[plugin-geo.md](plugin-geo.md). The plugin-facing search features themselves
(sorts, aggregations, `terminate_after`, fetch) are in the `search-*.md` files.

|---|---|---|
| `index/StandardDirectoryReader` (an NRT reader's view: own `SegmentInfos`, in-memory live docs) + `index/SegmentInfos.write` | `lucene-ffi/src/jvm_reader.rs::{ffi_open_jvm_reader, ffi_jvm_reader_search, ffi_close_jvm_reader, ffi_jvm_abi_version, JVM_ABI_VERSION, decode_node}` | **ported** M2-M9; ABI **33** (`JVM_ABI_VERSION`'s doc comment is the history). One native reader per Java searcher reader, opened from `SegmentInfos.write`'s bytes, checked per segment against the JVM's `maxDoc`s and masked with the JVM's live docs. The handle is an immutable `Arc`: a search holds no lock, so a slow query never blocks a refresh. Segments memory-mapped; a refresh reuses unchanged segments (`reopen_at`). Query blob: the recursive tree of every encodable node (core queries, points, geo, the M10 nodes below), depth-capped at 32; count-only runs `NoScores`. Gap: compound segments are copied, not mapped. Tests: unit against `multi_segment_scoring_index` (hits, score bits); malformed input; JVM-side `NativeSelfTest`. |
| -- (the Java binding: `org.lucenerust.opensearch.NativeBridge`'s downcalls) | `lucene-ffi/src/ffm_bridge.rs::{ffi_jvm_reader_search_sorted_alloc, ffi_jvm_reader_aggregate_alloc, ffi_jvm_reader_aggregate_tree_alloc, ffi_jvm_reader_document_alloc, ffi_jvm_reader_doc_freq, ffi_jvm_last_error, ffi_jvm_set_last_error, ffi_jvm_free_bytes}` | **rust-only**, Panama FFM (JDK 25, bundled with OpenSearch 3.8.0); the C ABI is called directly, arguments and results in per-thread native scratch memory (never heap arrays: only a `critical` downcall allows that, and it blocks safepoints). `ffm_bridge.rs` adds Rust-allocated result buffers for results sized after the work (`ffi_jvm_free_bytes`), `doc_freq`, and the last-error slot. Bench: empty call 12.4 ns (`gradle nativeBench`); in the node, native time FFM/JNI median 0.978x over 174 query shapes (noise 5-7%). A term query's `docFreq` shortcut and its search are two downcalls; the tree's norms cover only scoring clauses. |

## M10 T10.7: joins, spans, intervals, combined fields, function score

OpenSearch 3.8.0 shapes: **native** (encoded by the plugin's `ExtendedEncoder`)
or **falls back** (named reason). Proved by `NativeSelfTestM10` (hits, score
bits, counts, sorts, aggregations vs Lucene) and `e2e/m10_matrix.py`.

| Java | Rust | Status |
|---|---|---|
| `search/join/ToParentBlockJoinQuery`, OpenSearch's `OpenSearchToParentBlockJoinQuery` (`nested`) | `lucene-ffi/src/jvm_nodes.rs::{decode, SharedParents}` | **native**, every `score_mode`; parent bit sets cached per segment and filter (64 MiB, dropped with the last reader of the segment; `ffm_bridge.rs::ffi_jvm_parent_cache_stats`). `inner_hits` is the fetch phase. Falls back: another producer class (`join_parents`). Tests: `jvm_nodes::tests`. |
| `queries/spans/{SpanTermQuery, SpanNearQuery, SpanOrQuery, SpanFirstQuery, SpanPositionRangeQuery, SpanNotQuery, SpanContainingQuery, SpanWithinQuery, FieldMaskingSpanQuery}` | `lucene-ffi/src/jvm_nodes.rs::decode_span` | **native** (`span_multi` once rewritten). Falls back: `span_gap`, payload spans (`span_<Class>`). |
| `queries/intervals/IntervalQuery`, every Lucene `IntervalsSource` | `lucene-ffi/src/jvm_nodes.rs::decode_source` | **native**; a multi-term source's automaton sent as bytes, a repeating source's copies capped at the clause limit (`interval_repeating_count`). Falls back: the `script` filter, foreign sources (`interval_<Class>`). |
| `search/CombinedFieldQuery` | `lucene-ffi/src/jvm_nodes.rs::NODE_COMBINED_FIELD` | **native.** |
| -- (OpenSearch's `FunctionScoreQuery`) | `lucene-ffi/src/jvm_function_score.rs::{decode, OpenSearchFunctionScore}` | **rust-only**: `weight`, `field_value_factor`, `random_score`, numeric/date decays, filters, every mode, `max_boost`, as a values source under `FunctionScoreQuery` taking every ancestor's boost onto the sub-query; `random_score` on a long field hashes the bytewise smallest `Long.toString` as `FieldData.toString` sorts. **Differs:** libm's `log10`/`log`/`log1p`/`exp`, not HotSpot's. Falls back: `min_score`, scripts, geo decay, other field data (`function_score_*`). Tests: `jvm_function_score::tests`. |
| `parent-join`'s `has_child`/`has_parent`; `collapse` | -- | **falls back**: the join's from side runs in Java at rewrite over OpenSearch's `OrdinalMap`; collapsing needs a collapsed top-docs result the native path lacks. `more_like_this`, `common`, `parent_id` rewrite to shapes already native. |
