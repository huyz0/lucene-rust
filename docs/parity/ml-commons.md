# lucene-ml -- ml-commons' local model inference and remote connectors

[Index](../parity.md). Not a Lucene module: OpenSearch's ml-commons plugin
(3.9.0.0) runs deployed local models through DJL, with ONNX Runtime and
Hugging Face tokenizers underneath, and TorchScript models on libtorch.
`lucene-ml` runs the same models on the same tokenizer library, ONNX Runtime
and libtorch. The plugin's `ml` package serves the
REST API (`scripts/check-ml-plugin.py` compares it with a stock node).

| Java | Rust | Status |
|---|---|---|
| -- (DJL `HuggingFaceTokenizer.builder().optPadding(true)`) | `lucene-ml/src/tokenizer.rs::{load, encode, Encoded, MODEL_MAX_LENGTH}` | **rust-only** (port of ml-commons' tokenizer setup). Special tokens, `LONGEST_FIRST` truncation at the file's length capped at 512, the file's stride, batch-longest padding. Tests: unit tests; `tests/stock_vectors.rs`. |
| -- (DJL `OrtEngine` environment) | `lucene-ml/src/runtime.rs::{init, is_loaded}` | **rust-only**. One ONNX Runtime library and environment per process, one intra-op pool shared by every model (ONNX Runtime's default spinning). Tests: `a_second_init_keeps_the_first_runtime`. |
| -- (ml-commons `TextEmbeddingDenseModel`, `ONNXSentenceTransformerTextEmbeddingTranslator`) | `lucene-ml/src/text_embedding.rs::{TextEmbeddingModel, Config, Pooling, Tensor, pool, normalize_first_axis}` | **rust-only** (port of ml-commons). `input_ids`, `attention_mask`, and `token_type_ids` for `bert`/`albert`; MEAN, MEAN_SQRT_LEN, MAX, WEIGHTED_MEAN, CLS, LAST_TOKEN, NONE pooling; L2 normalization along the first axis. One text per run, as stock. Tests: `tests/stock_vectors.rs` (vectors recorded from a stock node, 27 model/pooling cases, relative 2e-5). |
| -- (ml-commons `SparseTokenizerModel`) | `lucene-ml/src/sparse_tokenize.rs::{SparseTokenizer, Weight}` | **rust-only** (port of ml-commons). Distinct token ids, decoded with special tokens skipped, weighted by `idf.json` (1.0 when absent). Tests: unit tests; `scripts/check-ml-plugin.py` (same weights by token and by id as stock). |
| -- (ml-commons `TextEmbeddingSparseEncodingModel`, `SparseEncodingTranslator`) | `lucene-ml/src/sparse_encoding.rs::{SparseEncodingModel, SparseOutput}` | **rust-only** (port of ml-commons). One text per run; each output's non-zero vocabulary weights, keyed by decoded token (special tokens dropped) or by id. Tests: `tests/stock_vectors.rs` (weights recorded from a stock node, by token and by id). |
| -- (ml-commons `TextSimilarityCrossEncoderModel`, `TextSimilarityTranslator`) | `lucene-ml/src/text_similarity.rs::TextSimilarityModel` | **rust-only** (port of ml-commons). Query and document tokenized as a pair, `token_type_ids` when the graph takes them, outputs without the batch axis. Tests: `tests/stock_vectors.rs` (scores recorded from a stock node). |
| -- (DJL `OrtSymbolBlock`, `Batchifier.STACK`) | `lucene-ml/src/onnx.rs::{OnnxModel, Output, Tensor, Feed, feeds_by_name, unbatch}` | **rust-only**. One session per model; an empty token sequence refused and the batch axis dropped as DJL does. Deviation: inputs are fed by name with or without the `input1.` prefix, and `token_type_ids` whenever the graph takes it, where DJL needs a sparse model's exact `input1.input_ids`/`input1.attention_mask` pair; every model stock runs runs here too. Float outputs only (the models stock serves are float). Tests: unit tests; `tests/stock_vectors.rs`. |
| -- (DJL `PtSymbolBlock`, `IValueUtils`; ml-commons `SentenceTransformerTextEmbeddingTranslator`, `HuggingfaceTextEmbeddingTranslator`) | `lucene-ml/src/torchscript.rs::{TorchScript, Input, TorchOutput, Data, run, float_output, DICT_FEEDS, PAIR_FEEDS}`; `lucene-ml/src/text_embedding.rs::TorchTextEmbeddingModel`; `SparseEncodingModel::torchscript`, `TextSimilarityModel::torchscript` | **rust-only** (port of ml-commons and DJL). DJL's input grouping (`input1.*` arrays as one dict argument, other names positional) and output flattening (tensors, lists, tuples, one-level dicts by key); a sentence-transformers model's outputs as given (FLOAT32 and INT64), a Hugging Face one pooled as its translator does into one `[1, dim]` `sentence_embedding`; cross-encoders fed all three arrays, as DJL does before a TorchScript model has run. Deviation: an output of another data type (INT32, BOOLEAN, FLOAT16) is refused with an error, where stock passes it through; the models stock serves return none. Tests: unit tests (a fake module); `lucene-ffi` `ml_torch.rs` (the stock vectors of the same weights' ONNX fixtures); `scripts/check-ml-plugin.py` torchscript section. |
| -- (DJL `LibUtils.loadLibTorch`) | `lucene-ffi/src/ml_torch.rs::{init, Module}`, `lucene-ffi/torch/lucene_torch.cpp` | **rust-only**. libtorch 2.5.1 loaded once in DJL's order; a C ABI shim built against libtorch's headers per C++ string ABI (`scripts/build-torch-shim.sh`), the one that resolves used. Deviation: stock pins libtorch to one intra-op thread; here a call running alone uses every physical core and concurrent calls split them, with OpenMP waiting passively (`OMP_WAIT_POLICY`, unless set): a sparse query encodes 1.8x faster and a document 2.1x on an idle node, and throughput under load stays at stock's. The system's libstdc++ is used over the one the pre-C++11-ABI build bundles. Tests: unit tests; `torchscript_models_through_handles`, `torchscript_models_give_stock_vectors` (CI runs the pre-C++11-ABI build stock downloads; both builds pass). |
| -- (the plugin's FFM bridge) | `lucene-ffi/src/ml.rs::{ffi_ml_runtime_init, ffi_ml_torch_init, ffi_ml_torch_open, ffi_ml_torch_text_embedding_alloc, ffi_ml_text_embedding_open, ffi_ml_text_embedding_embed_alloc, ffi_ml_sparse_tokenize_open, ffi_ml_sparse_tokenize_alloc, ffi_ml_sparse_encoding_open, ffi_ml_sparse_encoding_alloc, ffi_ml_text_similarity_open, ffi_ml_text_similarity_alloc, ffi_ml_model_close}` | **rust-only** (no Java counterpart: the plugin's native boundary). Model handles and the length-prefixed text and result encodings. Tests: unit tests. |
| -- (ml-commons `HFModelTokenizer`, `HFModelTokenizerFactory`, `HFModelAnalyzer`, `HFModelAnalyzerProvider`) | `lucene-ml/src/hf_analyzer.rs::{HfAnalyzer, Token}`, `lucene-ffi/src/ml.rs::{ffi_ml_hf_analyzer_open, ffi_ml_hf_analyze_alloc}`, `opensearch-plugin/.../ml/HfAnalysis.java` | **rust-only** (port of ml-commons). The `bert-uncased` and `mbert-uncased` pre-built analyzers and tokenizers and the `hf_model_tokenizer` type, from ml-commons' bundled vocabularies and idf weights: word pieces without special tokens over the whole text (overflow included), idf weight as a float payload, token or token-id terms by the type attribute, offsets in code points as DJL reports them. Tests: unit tests; `scripts/check-neural-plugin.py` (`_analyze` against stock, explain with payloads). |
