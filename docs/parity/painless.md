# lucene-painless -- Painless scripts run natively

[Index](../parity.md). OpenSearch's `lang-painless`: the plugin runs Painless's own front end and
sends the IR (`PainlessIr.java`); Rust compiles it to a register program and runs it with Painless's
runtime semantics (`def` dispatch, `DefMath`, casts, the allowlisted classes).

**Checked before it runs.** A script runs natively throughout, or not at all. `lucene-painless/src/check.rs::check` decides statically, on the specialised program, that every call, `def` access and cast resolves as Painless's would for
each class its static type admits (`PainlessIr.siteTable`), every `doc` read is a constant mapped field with a native reading, every `params` read folds, and
only served methods are used. Refused: regexes `regex` cannot match exactly
(`api/regex.rs::translate`), changes to live collection views, casts of views, method references
without a target. A refusal runs in Java, cached per script.

**No re-run.** A checked script that throws fails the search as in Java, same `ScriptException` (class, message, stack, position): the plugin runs it once more in Java (`PainlessScore.failure`) for the JVM's message and frames; stats count `script_errors`. A
runtime gap (`Unsupported`) is the plugin's failure and falls back. Tests: `tests/corpus.rs` and
`e2e/verify_opensearch.py::script_errors`. Gap: three scripts whose JVM `WrongMethodTypeException` message differs.
