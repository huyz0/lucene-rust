# lucene-tensor -- multi-vector (late-interaction) fields and MaxSim

[Index](../parity.md). Not a Lucene module: opt-in multi-vector fields of this
port's own design, for ColBERT-style late interaction. Values are `BINARY` doc
values, so the files are Lucene's; the `float` encoding is Lucene's own
`LateInteractionField` bytes, the other encodings are read by stock Lucene as
opaque binary values. The OpenSearch plugin serves them as the `multi_vector`
field and the `max_sim` query, in Rust. Quality figures
below are from BEIR SciFact and NFCorpus encoded with answerai-colbert-small-v1
(96 dims), against exact `MaxSim` over the whole corpus; speed from
`crates/lucene-tensor/benches/max_sim.rs`.

| Java | Rust | Status |
|---|---|---|
| `document.LateInteractionField` (`float` layout reused) | `lucene-tensor/src/encoding.rs::{TokenEncoding, encode, decode_into_blocks, blocks_of}` | **rust-only**. `float`: `int dim` then the floats, little-endian, byte for byte Lucene's. `float16` (`int -1`, dim, token count, IEEE half floats) and `int8` (`int -2`, dim, token count, a scale per token, signed bytes: `round(x / (max\|x\| / 127))`) store the tokens in blocks of 16, component-major, the layout `lucene-util/src/max_sim.rs` scores; a negative first `int` marks them, since Lucene's starts with a positive dimension. `blocks_of` scores `float16` in place and widens the others into a scratch buffer (`float` transposed as it is read). Every length read off a value is checked (truncated, ragged and unknown values are refused; a malformed `float` value gets Lucene's `LateInteractionField.encode` message). `float16` and `int8` take finite components only (`float16` up to 65504), `float` any float, as Lucene; a subnormal `int8` token keeps a non-zero scale. Measured: `float16` keeps nDCG@10 (0.740 SciFact, as `float`), `int8` too (recall@10 0.98 against exact). Tests: unit tests, `float` against `encode_multi_vector`; `tests/lucene_fixture.rs` decodes every `LateInteractionField` value in Java's `document_fields` index; `tests/golden.rs` pins every encoding's bytes, which the plugin's Java encoder must write too (`NativeSelfTestTensor`). |
| `search.LateInteractionFloatValuesSource` (`SUM_MAX_SIM` with dot product) | `lucene-tensor/src/score.rs::MaxSimQuery` | **rust-only**. Sum over the query's tokens of the best dot product with any document token (raw dot product, not `VectorSimilarityFunction.DOT_PRODUCT`'s `(1 + dot) / 2`, so the order is Lucene's and the score is ColBERT's). Lucene's refusals for empty and ragged queries; a value of another dimension is refused, and a value with no tokens scores `Float.MIN_VALUE` before the dimension is compared, as `SUM_MAX_SIM`. Measured (`benches/max_sim.rs`, 23 query x 236 document tokens, 96 dims, AVX-512 Xeon): `float16` 16 us, `int8` 25 us, `float` 33 us, against 73 us for the Lucene port's decode-and-compare path (the baseline is that port, not Java: the comparison is between layouts over the same `float` bytes, and the port's path already benchmarks against Java). Tests: unit tests; `tests/lucene_fixture.rs` scores Java's values bit for bit as the scalar `MaxSim` over `decode_multi_vector`'s tokens. |
| `search.LateInteractionRescorer` (`create`, `withFallbackToFirstPassScore`) | `lucene-tensor/src/values_source.rs::{MaxSimValuesSource, max_sim_rescorer, Missing}` | **rust-only**. A `DoubleValuesSource` over a field's `BINARY` doc values in any encoding, and a `DoubleValuesSourceRescorer` that replaces each hit's score with its `MaxSim` (a hit without a value scores 0 or keeps its first-pass score; Lucene's per-token `(1 + dot) / 2` is never negative, so 0 ranks a missing hit last there, while a raw `MaxSim` below 0 ranks under it here). Tests: `tests/rescore.rs` (two segments written by the index writer, every encoding ranks as exact `MaxSim`, Lucene's `LateInteractionRescorer` ranks the `float` field the same). |
| -- | `lucene-tensor/src/pooled.rs::pooled_mean` | **rust-only**. The unit-length mean of a multi-vector, the single vector a `knn_vector` field indexes for candidates. Measured: BM25 plus pooled-mean candidates, 100 to 300 reranked, match exact `MaxSim` nDCG@10 on SciFact (0.741 vs 0.740) and come within 0.007 on NFCorpus; MUVERA encodings (10,240 dims) did worse than the pooled vector and are not used. Tests: unit tests; `tests/golden.rs` pins its bits, which the plugin's `MultiVectorEncoding.pooledMean` must equal (`NativeSelfTestTensor`). |
| -- | `lucene-tensor/src/lib.rs::{Error, Result}` | **rust-only**. Crate error. |
| -- (the plugin's `multi_vector` field and `max_sim` query) | `opensearch-plugin/.../tensor/{MultiVectorFieldMapper, MultiVectorEncoding, MaxSimQuery, MaxSimQueryBuilder}.java`, `ExtendedEncoder.java::maxSim`; `lucene-ffi/src/jvm_max_sim.rs::decode` | **rust-only**. `multi_vector` (`dimension`, `encoding`: `float16` by default, `float` for Lucene's `LateInteractionField` bytes, or `int8`) keeps a document's token vectors (an array of arrays of numbers) as one binary doc value, written by the Java encoder in `encoding.rs`'s layouts; `_source` keeps them as sent; with `pooled: true` (dimension up to 1024, Lucene's vector limit) each document's pooled mean is also indexed in a hidden HNSW vector field (`<field>._pooled`, dot product; a value whose tokens sum to zero has none, so candidates never include it); the field takes no multi-fields. `max_sim` (`query_vectors`, optional `candidates`, `filter`, `boost`) is a Lucene `FunctionScoreQuery` over the documents with a value: each scores its `MaxSim` (0 when negative), and as a stock `rescore_query` with `query_weight: 0` it reranks a first-pass window. `candidates: n` (a `pooled` field) narrows the matches to the `n` documents nearest the query's pooled mean (the plugin's native top-k vector search, the filter applied during it), still scored by `MaxSim`; beside a `match` in a `bool` `should` it unions lexical and vector candidates for the rescore. Query tree node 44 runs it in Rust over `MaxSimValuesSource`; the Java scorer (`MultiVectorEncoding.maxSim`) is the kernels' scalar specification. Tests: `jvm_max_sim.rs` (every encoding through the native reader, refusals), `NativeSelfTestTensor` (native against Java, Lucene's `LateInteractionField` bytes too), `scripts/check-tensor-plugin.py` (a node: query, filter, rescore, candidates, both engines, no fallback, refusals); `scripts/bench-tensor-beir.py` measures each pipeline's nDCG@10 and latency on a BEIR dataset. |
