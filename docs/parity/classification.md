# lucene-classification -- text classifiers (M14 T14.3)

[Index](../parity.md). `org.apache.lucene.classification`: classifiers that learn from an index's
documents by searching it -- naive Bayes, k nearest neighbours, a boolean perceptron -- their
whole-document flavours, and the tools that evaluate them and split an index into training,
test and cross-validation sets. Java's classifiers take an `IndexReader`; here a `TrainingIndex`
carries the reader, its opened segments, norms and the JVM's `BytesRef` hash seed (equal scores
come out in `HashMap` order, which follows it).

Bench (ns per classification, Java vs Rust, host Windows, not the Linux CI; the runner built fat-LTO, the Java side is `ClassificationMicro` on the same jars, run back to back in two rounds, so the numbers are noisy by about ±25%): `cls_fuzzy3` 243k/300k vs 202k/224k (Rust faster, about 1.2x); `cls_knn3` 23k/28k vs 25k/27k (about even); `cls_bm25nb` 195k/211k vs 285k/296k (Rust about 0.7x, slower -- open); `cls_perceptron_train` 5.15M/5.23M vs 5.39M/5.35M (about 0.97x, open). Earlier single-run figures (Java 229,688 snb, 3,104 cnb, 29,889 knn3 and so on) were not reproduced under the same load and are superseded. The fuzzy gain came from building the Levenshtein automaton's byte classes from its ranges (not the dense table) and from reusing a term's compiled automaton across queries (`lucene-codecs/src/fuzzy.rs`).
